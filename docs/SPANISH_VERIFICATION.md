## Метод и ограничения

Скрипт [verify_spanish.py](../scripts/verify_spanish.py) использует существующие адаптеры,
общие постоянные лимиты источников, deadline 30 секунд и lease сборщика. На время сверки
управляемый worker остановлен, затем сервер запущен снова. Результат без тел матчей:
`data/qa/spanish-verification.json`. Долгоживущий документ содержит только метод и агрегаты.

Матчи сопоставлены по UTC-дате и явным соответствиям названий хозяев/гостей. ID поставщиков
не объединялись; нечеткий поиск не применялся. Явные aliases используются только для
сверки и не изменяют рабочие данные. Название первой команды Osasuna не приравнивается
к названию команды B. Несопоставленные записи могут означать даты/названия/ошибки источника,
а не обязательно отсутствие матчей. Причины требуют отдельного разбора.

Для женской лиги и кубка сравнивались разные представления **одного Sky Sports**.
Это подтверждает техническую согласованность сбора с контрольной страницей, но не
независимую достоверность и полноту поставщика. Live-минуты/таймы, точное окончание,
победители по пенальти и агрегатный счет против второго источника не сверялись.
Ни одно соревнование поэтому не получило полной пометки «Верифицировано».

Исторические карточки не записывались ни в SQLite, ни в файлы ответов. Использование
сентябрьских результатов для сверки не изменяет окно сбора и 72-часовое рабочее хранение.
Пометки записаны после успешной загрузки всех правильных контрольных страниц, с выборкой,
основанием и ограничениями. Пометки не повышаются по одному HTTP 200.

Первоначальный контрольный адрес Copa без префикса `spanish-` вернул 404. Исправлен адрес;

первого диагностического запроса снят адресно, с сохранением 20-секундного интервала.
