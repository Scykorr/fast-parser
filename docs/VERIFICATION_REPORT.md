# Отчёт проверки Fast Parser 0.7.0

Дата: 06.10.2026 (Europe/Moscow). Документ: 1.0.0. Проверена рабочая предварительная версия, не подтверждён стабильный релиз 1.0.

## Среда

Windows 11, Python **3.14.6**, локальная `.venv`, FastAPI/Uvicorn, SQLite WAL. Версии Python-пакетов зафиксированы в `requirements.lock`; `pip check` не обнаружил конфликтов. Браузерный тест — установленный Microsoft Edge 154.0.4258.53 через Playwright в headless-режиме, viewport 1280×720 и 390×844. Нагрузочный хост имеет 16 логических CPU; ограничения 2 vCPU / 4 GB не задавались.

## Реальные источники и запуск

- `source-check` реально получил HTTP 200 от OpenLigaDB и каталог из 75 актуальных футбольных записей после фильтрации.
- Worker загрузил реальные расписания bl1/bl2/bl3/pl/la1; пакет сезона преобразуется в матчи выбранного окна. ucl/dfb в первичном окне пусты.
- Реальные HTML-страницы Sky Sports нескольких дат дали расписания, завершённые результаты, текущие счета и переносы. Явные минуты получены у части карточек; точный тайм и конец не гарантируются.
- Сервер запущен на `127.0.0.1:8000`, проверены страница, JSON API и health. После остановки/повторного запуска сохранились настройки, каталог и матчи; постоянные состояния лимитов не сбрасываются.
- Платные ключи и сервисы не использовались. Непроверенные варианты и ограничения источников перечислены в [SOURCES.md](SOURCES.md).

## Автоматические сценарии

Команда: `scripts/check.ps1`. Последний результат: **32 passed**, 1 предупреждение о deprecated TestClient/httpx в новой Starlette. Также пройдены `compileall`, `node --check fast_parser/static/app.js` и `pip check`.

Проверены:

- Граница 72 часов, сухая/физическая очистка, anchor при неизвестном конце, поздно полученный достоверный конец, отсутствие продления от коррекции счёта.
- Маркеры удаления после рестарта, подтверждённый перенос/возобновление и обновление одного ID без дубля, отмена и неопределённые статусы.
- Неверные счета/лига/схема, пустые обязательные данные, отсутствие выдуманного LIVE у OpenLigaDB.
- HTML-карточки, явная минута/45+2, HT, FT, перенос, ошибка даты и страница блокировки.
- Пагинация по началу/ID без дублей, фильтры, лимиты ответа и 404 для истёкшего матча.
- 429/Retry-After, 403, CAPTCHA под HTTP 200, 503; постоянные лимиты и исключение второго collector по lease.
- Одно пакетное HTTP-чтение на 100 матчей, возобновление задания worker из БД после рестарта.
- IANA-валидация, обязательная UTC-зона абсолютных дат и окно через полночь.
- Origin/CSRF: разрешённое сохранение, отклонение чужого origin и отсутствующего токена.

Первый запуск pytest столкнулся с недоступным общим temp-каталогом хоста. Повторяемый скрипт теперь создаёт собственный уникальный `data/pytest-*`. Дополнительный тест восстановления первоначально проверял состояние до завершения асинхронного commit диагностики; ожидание исправлено, итоговый прогон успешен.

## Браузер

`scripts/test_browser.cjs` проверяет настоящий запущенный сервер и реальные сохранённые данные. Node.js/Playwright нужны только разработчику для этих тестов, приложение их не требует.

Проверки: страна → лига → матч; обе команды и карточка; ошибка/успех сохранения настроек; 100 переключений лиги; мобильный экран без внешнего переполнения; имя команды с HTML отображается текстом, XSS не выполняется; срок хранения истекает на экране даже при последующей недоступности backend. Не обнаружено ошибок JavaScript.

Последние 5 загрузок первого экрана: **1006, 78, 73, 69, 78 мс** (округлено). p95 100 переключений лиги: **25,3 мс**. Первый запуск холоднее последующих; эти цифры относятся к текущему небольшому реальному набору данных в локальной БД, не к внешнему времени получения результатов.

Скриншоты проверены визуально и сохранены в `data/qa/desktop.png` и `data/qa/mobile.png`, они содержат реальные матчи и автоматически удаляются по 72-часовой политике при работающем worker. Отчёт браузера с агрегатами — `data/qa/browser-report.json`.

Повторение в текущей среде:

```powershell
$env:PLAYWRIGHT_MODULE='C:\Users\Tony Fedos\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\node_modules\playwright'
node scripts\test_browser.cjs
```

На другом ПК установить Playwright для тестов либо указать свой путь в `PLAYWRIGHT_MODULE`; по умолчанию нужен Edge (`BROWSER_CHANNEL=msedge`). Тест сохраняет прежние настройки через UI и не покупает доступ. Запускать при включённом HTML-сборе и наличии проверенных международных матчей.

## Синтетическая нагрузка

Команда: `.venv/Scripts/python.exe -m scripts.benchmark`. БД создаётся отдельно в `data/benchmarks/<uuid>/football.sqlite3`; реальные матчи не изменяются.

Профиль: **100 000 синтетических матчей, 100 лиг, 1 000 неопределённых матчей, 20 одновременных in-process ASGI-клиентов, 200 запросов** списка со всеми названиями команд.

| Показатель | Последний замер |
|---|---|
| Вставка 100 000 | 15,44 с |
| API p50 | 221,1 мс |
| API p95 | **330,6 мс** |
| Удаление 1 000 истёкших строк | **25,0 мс** |
| HTML/CSS/JS суммарно gzip | **10 139 байт** |

Цель 500 мс для API выполнена на этом хосте. ASGI-замер не включает сетевой сокет/браузер; их работоспособность проверена отдельно. Профиль 2 vCPU / 4 GB и производительность браузера именно на 100k-данных ещё требуют отдельного прогона. Агрегаты: `data/qa/benchmark-report.json`.

## Не подтверждено этим отчётом

Семидневная стабильность, полный мировой охват, независимая правильность community-счетов, автоматический fallback между источниками, точная задержка от фактического конца, Docker/Linux, внешняя публикация с авторизацией, распределённые workers, полное покрытие DST и всех форматов каждого турнира. Не присваивать им статус «готово» по результатам текущих тестов.
