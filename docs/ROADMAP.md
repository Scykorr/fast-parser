## Правила версионирования

Использовать SemVer `MAJOR.MINOR.PATCH`: несовместимые изменения API/конфига — major; совместимые возможности/адаптеры — minor; исправления — patch. Для 0.x явно описывать возможные несовместимости. Версии продукта и документов независимы. API начинается с `/api/v1`; изменение схемы БД оформляется миграцией, а не ручным редактированием таблиц.

Каждый релиз содержит CHANGELOG: добавлено, исправлено, изменено, миграции, известные ограничения, подтверждённые проверки. Тег создавать только после успешной проверки. Поддерживать способ отката приложения; необратимые миграции требуют отдельного плана восстановления с учётом срока хранения.
