# Получение матчей другой программой

Версия продукта: 0.8.1. Дата: 06.10.2026.

Каталог возвращает `coverage_verification` отдельно от `collection_state`: доступность
сбора не означает верификацию лиги. Пометки и API обновления описаны в
[COVERAGE_VERIFICATION.md](COVERAGE_VERIFICATION.md). Журнал изменений матчей не содержит
обновления этих пометок; для них периодически перечитывайте каталог.

Запустите `start.cmd`. Программа на том же компьютере может читать JSON по адресу
`http://127.0.0.1:8000/api/v1`. Ключ и платный API не нужны. Сервер должен оставаться
запущенным. Не открывайте SQLite напрямую из программы-потребителя.

## Получение данных

- `GET /countries` — страны.
- `GET /competitions?country=Германия` — лиги; параметр URL-кодируется.
- `GET /matches?competition_id=ol:bl1:2026&limit=100` — страница матчей.
- `GET /matches/{id}` — карточка; 404 означает отсутствие или истечение хранения.
- `GET /changes?after=0&limit=100` — изменения для всех соревнований.
- `GET /diagnostics` — источники, heartbeat и матчи без результата более 24 часов.

Для `/matches` доступны `status`, `date_from`, `date_to`, `cursor`. Даты должны иметь
часовой пояс. Используйте `next_cursor` до его значения `null`. Максимальный limit — 200.
Имена команд находятся в `home_team.name` и `away_team.name`.

`last_checked_at` означает последнюю принятую проверку этого матча, а не время последнего
успеха источника вообще. `is_stale`, `freshness_age_seconds`, `freshness_threshold_seconds`
и `source_state` помогают показывать задержку. Порог равен двум настроенным интервалам
для текущего статуса. Это индикатор задержки, а не гарантия достоверности результата.
Минута, тайм, точное окончание могут быть `null`; не вычисляйте их по текущему времени.

## Первая и последующие синхронизации

1. Прочитайте `/changes?limit=1` и сохраните `watermark` как стартовый курсор.
2. Загрузите полный список через `/matches` и его страницы.
3. Прочитайте `/changes?after=<стартовый курсор>`, чтобы учесть изменения во время загрузки.
4. Для каждого события `upsert` замените локальную карточку по `match_id`; для `deleted`
   удалите ее. Сохраняйте `next_after` только после применения всей страницы.
5. Пока `has_more=true`, продолжайте чтение. Затем повторяйте опрос, например, раз в 15 секунд.

`seq` — возрастающий числовой курсор, устойчивый к нескольким изменениям в одну секунду.
Событие содержит актуальную карточку на момент чтения, а не историческую копию. Повторение
событий допустимо; обработка должна быть идемпотентной. При фильтрации своей лиги все равно
продвигайте общий курсор; если карточка переместилась в другую лигу, удалите ее из своей выборки.
У удаления достаточно ID: локальная программа уже знает принадлежность сохраненного матча.

Журнал хранится семь дней и содержит только ID, тип события и время, без истории счетов
и названий. HTTP 410 требует заново выполнить полную синхронизацию. После восстановления
базы из резервной копии также нужна полная синхронизация: старые курсоры использовать нельзя.
Существующие карточки при миграции не создают исторических событий — первая полная загрузка
обязательна. Самостоятельно скрывайте карточку в `expires_at`, даже если сервер недоступен;
событие удаления появится при очистке, обычно в течение пяти секунд работы worker.

## Пример Python

```python
import json
from urllib.request import urlopen
from urllib.parse import urlencode

base = "http://127.0.0.1:8000/api/v1"
params = urlencode({"competition_id": "ol:bl1:2026", "limit": 100})
with urlopen(f"{base}/matches?{params}", timeout=10) as response:
    page = json.load(response)
for match in page["items"]:
    print(match["home_team"]["name"], match["away_team"]["name"],
          match["score_home"], match["score_away"], match["is_stale"])
```

Чтение не требует CSRF. Изменение настроек предназначено для web UI и защищено Origin/CSRF.
API рассчитан на один компьютер; доступ из сети и система токенов в этой версии не реализованы.
# Дополнение 0.9.0: официальные источники

Матчи: `official_source`, `source_role` (`primary`/`legacy_unofficial`) и `source_url`
(адрес публичной страницы, null у старых карточек). Лиги также имеют `collection_allowed`.
Официальные ID: `ll:primera-division:2026`, `ll:segunda-division:2026`; ID матчей `ll:<id>`.
`official_source=true` не означает `coverage_verification.status=verified`.
В official_only=true запрос sync неофициальной лиги возвращает 422 с объяснением;
sync официальной лиги возвращает 202, сохраняя cooldown. Настройки содержат official_only,
диагностика — source_policy и состояние официального источника.

# Английские лиги — 0.10.0

Официальные competition_id: `pl:premier-league:2026`, `efl:championship:2026`.
Матчи имеют ID `pl:2026:<id>` и `efl:2026:<id>`; сезон включен для защиты от повторного
использования ID. source: `premierleague_official` / `efl_official`;
official_source=true, source_role=primary, source_url — публичный endpoint организатора.
Минута Premier League доступна только при наличии в live-ответе; тайм и точное окончание
nullable. Остальные контракты API v1 и 72-часовое хранение сохранены.

# Итальянские лиги и дата без времени — 0.11.0

Официальные competition_id: `sa:serie-a:2026`, `sb:serie-b:2026`; source:
`seriea_official` / `legab_official`. ID матчей включают сезон: `sa:2026:<matchId>` и
`sb:2026:<data-match-id>`. Происхождение и адрес доступны в official_source/source_role/source_url.
Новое nullable-поле `scheduled_date` содержит YYYY-MM-DD организатора, если день известен;
kickoff_at=null означает отсутствие точного часа. Не превращайте scheduled_date в полночь
или время окончания. Для таких карточек date_from/date_to фильтруют календарный день:
границы с неизвестным часом рассматриваются как дни, end в полночь исключает этот день,
end с ненулевым временем включает пограничный день. Это приблизительное календарное
сопоставление, а не точная проверка момента UTC; даты не переводятся в часовой пояс клиента
без известного времени. Точные kickoff_at сохраняют прежние >= start / < end правила.
Новые поля совместимы с API v1; SQLite v3 без миграции.

## Германия — 0.12.0

Новые competition_id: `dfl:bundesliga:2026`, `dfl:2bundesliga:2026`.
Источник `bundesliga_official`, official_source=true, source_role=primary.
Запрашивайте `/api/v1/competitions` для актуальных сезонных ID, затем
`/api/v1/matches?competition_id=dfl%3Abundesliga%3A2026`.
Существующий контракт сохранен: kickoff_at/finished_at/period/elapsed_minutes nullable,
при неизвестном времени scheduled_date предварительный. raw_status сохраняет статус DFL;
не выводите live из текущего времени или наличия счета. Подробнее: [GERMAN_SOURCES.md](GERMAN_SOURCES.md).
