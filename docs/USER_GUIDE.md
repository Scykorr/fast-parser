# Руководство пользователя Fast Parser

Продукт: 0.8.1, рабочая предварительная версия. Документ: 1.2.0, 06.10.2026.

Лиги в списке имеют пометки верификации; непроверенные лиги доступны как обычно. После
выбора лиги блок над матчами показывает, что проверено, выборку, основание и дату пометки.
Нажмите «Обновить пометку» после выполненной сверки. Для «Верифицировано» отметьте расписание
и результаты, заполните выборку и основание; для ограниченной сверки используйте «Частично».
Подробности: [COVERAGE_VERIFICATION.md](COVERAGE_VERIFICATION.md). Состояние сбора и свежесть
не зависят от пометки. Новые лиги, источники и сезоны начинают непроверенными.

В 0.8.1 база обновляется до v3, перед переходом создается `.v1.bak` или `.v2.bak` в зависимости
от предыдущей схемы. Эти копии обслуживаются так же, как копия миграции 0.8.0, описанная ниже.

## Что установлено

В папке проекта находятся приложение, веб-интерфейс, виртуальное окружение `.venv` с Python **3.14.6**, зафиксированные зависимости `requirements.lock` и тесты. Покупать API-ключ не требуется. Сбор работает, пока запущен Python-процесс и есть интернет.

Данные и настройки сохраняются в `data/football.sqlite3`. При перезапуске они не теряются. `.venv` и `data` исключены из Git. Виртуальное окружение нужно пересоздать при переносе проекта на другой компьютер/путь.

## Запуск на этом компьютере

1. Откройте папку `D:\PycharmProjects\fast_parser`.
2. Запустите `start.cmd` двойным щелчком; оставьте консоль сервера работающей.
3. В браузере откройте **http://127.0.0.1:8000**.
4. Дождитесь заполнения. Каталог загружается автоматически, затем выбранные лиги и HTML-страницы. Первый сбор занимает несколько минут из-за ограничения частоты.

Альтернативный запуск из PowerShell:

```powershell
cd D:\PycharmProjects\fast_parser
.\.venv\Scripts\python.exe -m fast_parser serve
```

Если порт занят, используйте `serve --port 8001` и адрес `http://127.0.0.1:8001`. Для остановки запустите **stop.cmd** двойным щелчком либо нажмите Ctrl+C в консоли. Для другого порта: `stop.cmd --port 8001`. Закрытие браузера не останавливает сбор. Сон/выключение ПК приостанавливают его; после восстановления задания продолжаются с сохранением лимитов.

`stop.cmd` посылает локальный запрос только экземпляру этого проекта и порта, ожидает корректного завершения сервера/встроенного worker и не завершает другие Python-процессы. Отдельный `run-worker` останавливается Ctrl+C в его консоли. Сервер, запущенный до появления stop.cmd или напрямую через uvicorn/Docker, один раз остановите прежним способом; после запуска через start.cmd управление stop.cmd будет доступно. После аварийного завершения возможен устаревший контрольный файл: тогда остановка сообщает, что завершение не подтверждено, без принудительного убийства процесса.

## Создание окружения на новом компьютере

```powershell
py -3.14 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock
.\start.cmd
```

Активация окружения не нужна: команды используют его Python напрямую. Минимум проекта — Python 3.13, проверка выполнена на 3.14.6. На Linux заменить `py -3.14` на `python3.14`, а `.venv\Scripts\python.exe` на `.venv/bin/python`.

Docker-вариант: `docker compose up --build`; данные сохраняются в папке `data`. Linux/Docker подготовлены, но на этом Windows-компьютере не проверены. Docker не обязателен для обычного запуска.

## Выбор и просмотр матчей

Выберите **страну → лигу → матч**. Поля поиска над списками помогают найти название. В таблице нажмите строку или выберите её клавишей Enter. Названия хозяев и гостей показаны в списке, строке и карточке, счёт — в том же порядке.

«Международные» содержит международные турниры, «Страна не указана» — записи без классификации. Лиги дополнены сезоном и источником. Один турнир может появиться отдельно у двух источников: автоматического объединения по похожим именам нет.

Фильтры дат и статуса изменяют **просмотр сохранённых данных**, а не внешний сбор. Конечная дата в интерфейсе включительна; внутри она переводится в начало следующего дня в выбранном часовом поясе. Начальный обзор — последние 3 и следующие 7 дней.

При большом количестве нажмите «Загрузить ещё»; страница содержит до 100 матчей. Поиск матча работает по загруженным строкам. Автообновление повторно загружает ранее открытый объем страниц; смена фильтров или лиги начинает с первой страницы.

В карточке отображается актуальность. «Данные задержаны» означает превышение двух интервалов проверки
или ошибку источника; сохраненный счет может быть устаревшим. Диагностика показывает число матчей
без результата более 24 часов. Они перепроверяются, но окончание по времени автоматически не угадывается.
Получение данных другой программой описано в [API_INTEGRATION.md](API_INTEGRATION.md).

При первом запуске 0.8.0 существующая база v1 обновляется до v2. Перед этим создается
`data/football.v1.bak`. Для отката остановите приложение и восстановите копию базы,
удалив оставшиеся SQLite-файлы WAL/SHM только при остановленных процессах. Копия содержит
старые данные матчей; worker удаляет ее через 72 часа после создания. Самостоятельные копии
обслуживаются владельцем. Восстановление копии еще требует отдельного эксплуатационного теста.

## Значение счёта и времени

- `— : —` — счёт не предоставлен, это не 0:0.
- «Идёт» и минута — последние сведения источника, а не самостоятельно увеличиваемый таймер.
- Тайм, перерыв и дополнительное время показываются только при явном обозначении источником.
- OpenLigaDB не передаёт достоверный текущий live-статус: начавшийся незавершённый матч может иметь «Статус уточняется».
- У завершённого матча точное время конца может отсутствовать. Тогда отдельно указано первое обнаружение завершения.
- Основное/дополнительное время и пенальти остаются пустыми, если источник не разделяет результаты. Общий счёт не подменяет эти поля.
- При задержке live-данных показывается последний статус с предупреждением. Проверяйте поле «Последние данные».

Часовой пояс по умолчанию `Europe/Moscow`; его можно изменить. Окончание не вычисляется из начала плюс предполагаемая длительность.

## Обновление и настройки

«Обновить экран» читает локальную БД, не запрашивая сайты. Автообновление — каждые 15 секунд в активной вкладке; скрытая вкладка не опрашивается.

«Проверить источник» ставит фоновую задачу с теми же лимитами. Для OpenLigaDB лига должна быть включена. HTML-задание обновляет общие страницы всех присутствующих там лиг.

В «Настройках сбора» доступны часовой пояс, скользящее/абсолютное окно, глубина назад 0–3 дня и вперёд 1–90, интервалы расписаний/live/итогов, окна работы и лиги OpenLigaDB. Пример окна: `08:00-23:00`; несколько через запятую, пусто — круглосуточно, переход через полночь поддерживается.

Общий HTML-сбор Sky Sports включён по умолчанию и может быть отключён. Отдельный выбор лиг на общей HTML-странице пока не поддерживается. Изменения применяются после текущего запроса без перезапуска сервера.

Интервалы не обходят ограничения: OpenLigaDB — не чаще одного запроса в 12,5 секунды; HTML — раз в 20 секунд. Это внутренние консервативные пределы, а не официальные квоты. При ошибках паузы растут. Включение всего каталога ухудшает свежесть; выбирайте необходимые лиги.

Абсолютные даты задаются с UTC-смещением: `2026-10-06T00:00:00+03:00` — `2026-10-14T00:00:00+03:00`, конец не включается. Длина диапазона ≤ 90 дней. Историческая загрузка старше трёх дней от текущего времени не выполняется, чтобы не возвращать удалённые результаты без точного конца.

## Правило 72 часов

Матч скрывается через 72 часа от достоверного окончания, иначе от первого обнаружения завершения. Во втором случае хранение может быть дольше 72 часов от фактического конца. Исправление счёта срок не продлевает.

Истёкшие записи скрыты в API, удаляются из БД пачками и исчезают с экрана. Минимальные маркеры ID препятствуют повторному появлению. Неопределённые/перенесённые записи не удаляются по правилу завершения. Отмена имеет срок 72 часа от обнаружения.

QA-скриншоты в `data/qa` очищаются через 72 часа при работающем worker. Программа не контролирует пользовательские внешние копии/бэкапы: если нужен строгий срок для всех копий, не создавайте долгоживущие выгрузки.

## Диагностика

Раскройте «Покрытие и состояние источников»: каталог, включённые лиги, успешные выборки, последний успех и ошибки. Успех выборки не подтверждает полный мировой охват.

| Симптом | Действие |
|---|---|
| Страница не открывается | Проверить консоль и адрес/порт |
| Каталог пуст | Дождаться загрузки, проверить интернет и ошибки источника |
| Лига есть, матчей нет | Включить сбор лиги, проверить даты; в окне может не быть матчей |
| HTTP 429 | Дождаться cooldown/Retry-After; частые клики не помогут |
| HTTP 403/CAPTCHA | Проверить доступ обычным способом; затем явно разрешить повторную проверку в диагностике. Обхода блокировок нет |
| Карантин HTML | Предыдущие данные остаются до expiry; требуется исправление адаптера |
| CSRF/origin ошибка | Перезагрузить страницу; при рестарте сервера токен меняется |
| Минута/тайм отсутствуют | Ограничение источника, покупать API не требуется |

CLI из папки проекта:

```powershell
.\.venv\Scripts\python.exe -m fast_parser validate-config
.\.venv\Scripts\python.exe -m fast_parser coverage-report
.\.venv\Scripts\python.exe -m fast_parser plan-collection
.\.venv\Scripts\python.exe -m fast_parser cleanup --dry-run
```

`source-check` проверяет каталог OpenLigaDB. Разовые `sync-fixtures`/`sync-results` собирают включённые лиги OpenLigaDB с теми же лимитами; перед ними остановите сервер. HTML собирается worker. Для отдельного worker установите `FAST_PARSER_WORKER=0` у веб-сервера и запустите `run-worker` в другой консоли; по умолчанию это не нужно.

Документация HTTP API: `/docs` на этом же сервере. Сервер ограничен localhost. Публикация для других компьютеров пока не является проверенным безопасным сценарием.

## Проверки после изменений

```powershell
.\scripts\check.ps1
.\.venv\Scripts\python.exe -m scripts.benchmark
```

Первая команда запускает тесты в изолированной новой папке `data/pytest-*` и проверяет синтаксис. Вторая измеряет синтетическую нагрузку в отдельной БД и не меняет реальные матчи. Браузерные проверки и границы замеров: [VERIFICATION_REPORT.md](VERIFICATION_REPORT.md).

Дальнейшие задачи: [ROADMAP.md](ROADMAP.md), ограничения: [IMPROVEMENTS_AND_BOTTLENECKS.md](IMPROVEMENTS_AND_BOTTLENECKS.md).
# Официальная сверка испанских лиг

Остановите приложение через `stop.cmd`. Выполните
`.venv\Scripts\python.exe -m scripts.verify_laliga_official` для отчета по официальным
страницам Примеры и Сегунды, затем запустите `start.cmd`. При необходимости обновления
пометки Примеры добавьте `--apply`: обновление произойдет только после успешного полного
прогона. Без флага пометки не меняются. Проверка требует сетевого доступа, соблюдает
30 секунд между официальными запросами; при сбое повтор ограничен. Сегунда проверяется
как источник, ее рабочий сбор пока не подключен. Подробности: [SPANISH_VERIFICATION.md](SPANISH_VERIFICATION.md).

# Основной режим 0.9.0

В настройках по умолчанию включено «Только официальные бесплатные источники».
Выберите страну «Испания», затем «Примера · LaLiga» или «Сегунда · LaLiga».
Текущий тур загружается первым, соседние туры — постепенно с интервалом не менее 30 секунд.
Кнопка проверки ставит официальный сбор в очередь и не отменяет ограничение сайта.
Официальный источник отмечается отдельно от верификации; новые лиги пока не верифицированы.
Прежние записи каталога доступны, но их неофициальный сбор в основном режиме отключен.
Остальные страны требуют подключения сайтов организаторов. Детали: [OFFICIAL_SOURCES.md](OFFICIAL_SOURCES.md).
# Англия в 0.10.0

Обновите страницу браузера и выберите «Англия» → «Премьер-лига · Premier League» либо
«Чемпионшип · EFL». При первом запуске Premier League сначала загружает названия команд,
затем матчи после интервала 30 секунд. Чемпионшип заполняется постранично. Кнопка проверки
ставит соответствующий источник в очередь; квоты не отменяются. В карточке видны команды,
статус, счет и официальный адрес. «Не верифицировано» означает отсутствие полной сверки
покрытия, а не неофициальный источник. Детали: [ENGLISH_SOURCES.md](ENGLISH_SOURCES.md).
# Италия в 0.11.0

Обновите страницу и выберите «Италия» → «Серия A · Lega Serie A» или «Серия B · Lega B».
Серия A на первом запуске определяет сезон, затем через общий интервал 30 секунд читает
матчи. Серия B сначала загружает текущий тур, соседние страницы появляются постепенно.
При неизвестном часе отображается день и «время уточняется»; это не точное начало матча.
В карточке видны команды, статус/счет, исходный статус и официальный адрес.
Источники официальные; пометка верификации пока неполная. Детали: [ITALIAN_SOURCES.md](ITALIAN_SOURCES.md).

## Германия — версия 0.12.0

После запуска выберите «Германия» → «Бундеслига · Bundesliga» или «Вторая Бундеслига · Bundesliga».
Выбирайте запись с пометкой официального источника; старые OpenLigaDB остаются отдельно.
Матчи отображают команды, начало и счет/статус; карточка показывает ссылку источника.
Первый сбор обеих лиг занимает минимум два разнесенных на 30 секунд запроса.
«Проверить источник» обновляет план, но не отменяет лимит/блокировку.
Пометка покрытия по умолчанию не верифицирована: не путайте ее с официальностью сайта.
Минута/тайм Германии пока не подтверждены; неизвестная фаза отображается как уточняемый статус.
При неподтвержденном времени показывается предварительная дата и «время уточняется».
