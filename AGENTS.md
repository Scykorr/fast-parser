## Неизменные требования пользователя

- Данные бесплатно: бюджет на API равен нулю. Не добавляй обязательную оплату,
  платный аккаунт, API-ключ платного сервиса или зависимость от пробного тарифа.
- Основной сбор — официальные публичные сайты организаторов/федераций и сервисы,
  которыми эти сайты реально пользуются. Бесплатный агрегатор не становится официальным.
- `official_only=true` по умолчанию; OpenLigaDB/Sky — сохраненный legacy, без
  автоматической подмены официальных результатов. Каталог не сокращать из-за непроверенности.
- Официальность, работоспособность сбора, актуальность и независимая верификация —
  разные свойства. HTTP 200 не дает права выставить `coverage_verification=verified`.
- Python и легкий web UI; обе команды, счет, начало, статус и доступные тайм/минута.
  Не выдумывать недоступные минуты, часы, счет, конец матча или тайм.
- Рабочее хранение финальных/отмененных карточек — 72 часа от достоверного конца либо
  первого наблюдения финала. Повторный опрос не должен продлевать этот срок.
- Другие локальные программы читают HTTP API v1, а не изменяют SQLite напрямую.
- CAPTCHA/401/403 останавливают источник. Не обходить challenge, не подбирать токены,
  не менять прокси/личность клиента ради обхода. Retry-After и постоянные квоты соблюдать.

## Принципы реализации

- Маленькие изменения в существующей архитектуре, без необоснованного нового стека.
- Чистый разбор в адаптере; HTTP, планирование и квоты в `collector.py`; сохранение,
  TTL и события в `storage.py`; представление API в `app.py`; UI в `static/app.js`.
- Используй `Collector.fetch()`, а не отдельный httpx-клиент внутри производственного адаптера.
- У каждой лиги/сезона/источника стабильные ID; не объединять команды нечетким поиском.
- Партия данных проверяется до импорта: лига, сезон, тур/страница, уникальность ID,
  команды, даты/зона, счет финала. Неизвестный статус — `unknown` с `raw_status`.
- UTC с offset для точного времени; `scheduled_date` отдельно для дня без часа.
- Новые данные не отменяют финал без более нового `source_updated_at` с обеих сторон.
- Состояние пагинации и квот должно переживать рестарт; одна задача на источник,
  общий лимит для нескольких лиг одного организатора. Lease нельзя отключать ради теста.
- Блокирующий Store/парсинг в async-worker запускать через `asyncio.to_thread`.
- Сохранять localhost/Origin/CSRF/CSP; тексты источников выводить через textContent.
- Изменение схемы БД требует миграции/копии/проверки восстановления. API ломать только
  с объявленной версией и переходом клиентов. Добавление nullable-полей обычно совместимо.

## Проверка и завершение

- Интерпретатор проекта: `.venv\Scripts\python.exe`. В проекте проверен Python 3.14.6,
  декларативный минимум `pyproject.toml` — 3.13.
- Основная проверка: `.\scripts\check.ps1` (pytest с отдельным basetemp, затем compileall).
  Для полностью изолированного запуска см. `docs/DEVELOPER_GUIDE.md`.
- JS: `node --check fast_parser/static/app.js`; browser smoke имеет legacy-предусловия,
  описанные в руководстве. Не считать их провал ошибкой нового адаптера автоматически.
- Тесты контракта — синтетические, сеть — MockTransport. Реальные контрольные запросы
  отдельно, с квотами; не сохраняй полный сезон/raw payload в Git.
- `data/`, `.venv/`, логи, БД/WAL, stop-token, raw HTML и реальные скриншоты не коммитить.
- Обновить паспорт источника/ТЗ/roadmap/риски/отчет по фактическому изменению.
  Для документационных правок без изменения поведения версия продукта не повышается.
- В отчете указать что проверено, что осталось и почему. Не заявлять мировой охват,
  полный live или завершенный недельный пилот без доказательств.
- Коммит/пуш — по запросу пользователя. Не считать предыдущую отправку постоянным
  поручением публиковать каждую последующую правку.

## Известные особенности, которые нельзя «случайно исправить» подменой требований

РПЛ в каталоге, но адаптера нет: API collection_supported/collection_allowed=false,
причина CAPTCHA, source rpl_official заблокирован, sync/reset возвращают 422.
Не включай РПЛ изменением одного флага. Сначала нужен подтвержденный официальный контракт.
`competitions.state=verified` — историческое имя успешного сбора, не отметка покрытия.
`enabled_leagues` пока управляет legacy OpenLigaDB, официальные workers работают отдельно.
Перед переносом проекта `.venv` пересоздают; локальные данные и настройки не входят в Git.
